## 1. Scope and no-change statements

- Presentation plus narrowly-scoped screen behaviour only. The
  `business-analyst` no-change statements
  (`mvp-requirements.md` section 10.1: all MVP FR/NFR wording
  unchanged, refusal semantics unchanged, no data-model impact,
  no new business rules) hold for testing too.
- The `traceability-matrix.md` 57-row MVP coverage count stands
  unchanged: AC-DSK rows live in a dedicated rollout slice
  (`traceability-matrix.md` section 4), never as new MVP rows,
  and no existing matrix guard may cite this rollout as its
  guard.
- Refusal-condition tests stay untouched: `CONFLICT`,
  `STATE_ILLEGAL`, `VALIDATION_FAILED`, `SETTLEMENT_REQUIRED`,
  `IDENTITY_LOCKED`, and `UNAUTHENTICATED` still fire on exactly
  the same conditions — only on-screen wording is plain
  stand-in-readable sentences (`FR-DSP-3`). A screen-PR diff
  that alters any refusal condition is out of scope and fails
  review.
- The #581 change is a narrowly-scoped input-mechanism behaviour
  change on the Book screen only (two date fields become
  app-localized PrimeVue DatePickers): payload dates stay
  canonical ISO `yyyy-mm-dd`, a real day change keeps the existing
  `onStayInput` quote path, a locale switch only re-renders the
  same calendar day, malformed or incomplete entry never reaches
  the payload, and one new catalogue placeholder key ships in
  both locales. Every other date surface (business-date header,
  quote/Folio desk dates, Stay/Folio fields), print output,
  refusal condition, and backend or contract shape stays out of
  scope; its guard is D15 and its map row is AC-DSK-15 in
  section 4.
- The #582 change is a narrowly-scoped input-mechanism behaviour
  change on the Folio and Print open-folio steps only (a select of
  the business date's in-house stays leads, the stay-ID text field
  stays visible as the manual fallback): the identifier sent to
  `GetFolioBalance`, `PostCharge`, and `RecordPayment` is the same
  value typed entry sent, a failed or empty list read degrades to
  manual entry with a plain notice, and four new catalogue keys
  ship in both locales. Print output, refusal conditions, the
  booking-reference field, Onboarding room creation, and backend or
  contract shapes stay out of scope; its guard is D16 and its map
  row is AC-DSK-16 in section 4.
- The #586 change is a narrowly-scoped flow-timing behaviour
  change on the Stay check-in panel only: the arrival pick loads
  the booking and the booked-type ready rooms through the existing
  `GetReservation` + `ListRoomsByState('vacant-inspected')` read
  pair and filter, a valid room selection clears the
  `Pick a ready room first.` message, and the commit stays on the
  Check in button (no room-pick commit, no step-structure
  redesign). The same single-candidate auto-select, explicit empty
  placeholder plus amber hint, unknown-reference / no-ready-rooms /
  `need_arrival` / `need_room` / `CONFLICT` strings, request bodies,
  catalogue keys, and both locales stay exactly as specified; move,
  times, and checkout flows are untouched. Its guard is D17, its
  map rows are AC-DSK-17 and `FR-CIP-1`..`FR-CIP-4` in section 4,
  and its traceability row lives in section 9 of
  `traceability-matrix.md`.
- The #588 change is a narrowly-scoped behaviour change on the Stay
  check-out panel only: a committed close now releases the departed
  room to `vacant-dirty` through the existing `ReleaseRoom`
  operation (the room number from the departing row, the signed-in
  staff name as `actor`) and reloads the desk once afterwards, and
  the no-unpaid-close rule now holds on every route to the close
  (button, dialog confirm, replayed or double click) against the
  `GetFolioBalance` read performed at that moment, with a recorded
  `RecordOpenBalanceApproval` object (identity, fixed-set role,
  recorded time) as the only exception. `CheckOut`, `ReleaseRoom`,
  `GetFolioBalance`, and `RecordOpenBalanceApproval` keep their
  request bodies; no backend, contract, schema, stored-value, or
  print change is involved; the check-in panel, refusal conditions
  for every other cause, and the charging economics stay untouched.
  Its guard is D18, its map rows are AC-DSK-18 and
  `FR-CKO-1`..`FR-CKO-5` in section 4, and its traceability rows
  live in section 10 of `traceability-matrix.md` (the
  `AC-DSK-18` condition lands with the #597 product spec PR and
  the `FR-CKO-*` ids with the #598 requirements spec PR, so the
  three spec PRs precede the #588 implementation PR). The same
  change
  corrects a stale claim in this spec's guard set: the QA-EDGE-8
  check-out case read the `vacant-dirty` turn as a server-side
  effect of `CheckOut` (`app/src/views/desk-edge-guards.test.ts:840-849`,
  `:908-947`), which the API desk loop contradicts
  (`script/e2e-desk-loop.sh:422-423`); the rewrite keeps the
  candidate half and replaces the check-out half with the release
  obligation, with a note.
- Catalogue rule holds (`NFR-I18N-1`, extended by `NFR-DSK-1`):
  every new or changed string ships in both `messages/en.json`
  and `messages/vi.json` with placeholders intact, and
  `script/catalogue-coverage-check.sh` is green on every screen
  PR. New keys land through the normal catalogue process:
  `desk.rooms.*`, `desk.onboarding.*`, `stay.checkin.*`,
  `desk.empty.*`.
- `data-testid` hooks stay: each screen PR keeps every hook the
  guards below rely on (or moves it with its test), updates
  characterization tests where markup changed, and deletes no
  test without replacement.
- Open owner calls constrain two guards (recorded on the
  affected sub-issue with the owner decision, never assumed):
  Rooms-map per-card action placement (#424) — D6 asserts a
  read-only map only and no action is invented; wizard steps
  2–4 content (Refs #438) — steps 2–4 are now specified, not
  assumed: exact fields and validation live with
  `business-analyst` (`mvp-requirements.md` section 11,
  `FR-DSK-8..10`, PR #442), the per-flow diagram with
  `architect` (LLD section 13.4 node J, PR #443), and the
  guard assertions below (D10–D12). D7 keeps covering launch,
  step 1, and the seeded no-launch rule only.
